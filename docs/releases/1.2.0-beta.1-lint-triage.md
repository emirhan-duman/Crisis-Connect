# Android lint triage — 1.2.0 Early Access · Beta 1

The API 37 / AGP 9.4.1 source snapshot initially introduced 89 diagnostics above the existing
public baseline. Every diagnostic was reviewed; `warningsAsErrors` and the fatal lint checks remain enabled.

## Corrected or narrowly explained in source

| Initial diagnostics | Disposition |
| --- | --- |
| 2 `NewApi` | Guard watch SOS notification-channel creation on API 26+, preserving notification support on API 24/25. |
| 1 `SwitchIntDef` | Treat an unknown rescue-module installation state as a failed installation and clear the pending UI state. |
| 7 `InlinedApi` | Add Android 15 / Android 14 extension-12 checks before satellite transport inspection. Explain narrowly scoped inlined intent/permission strings whose selection is driven by the SDK argument. |
| 7 `StaticFieldLeak` | Verify every singleton stores `applicationContext`; also normalize the disaster-network callback closure to the application context. Suppress only those verified singleton references. |
| 10 `SetTextI18n` | Move independent-watch phone setup and approval text into English/Turkish string resources, including formatted device labels and fingerprint prompts. |
| 1 `Typos` and 1 `UnusedResources` | The `android_wear_capabilities` array and `crisis_connect_phone_v1` token are reserved Data Layer discovery inputs. Keep their names, mark them non-translatable, and explicitly preserve the array during release resource shrinking. |

Android documents satellite transport as available from API 35 and Android 14 extension 12:
[NetworkCapabilities.TRANSPORT_SATELLITE](https://developer.android.com/reference/android/net/NetworkCapabilities#TRANSPORT_SATELLITE).

## Accepted baseline entries (60)

| Count | Diagnostic | Reason |
| --- | --- | --- |
| 11 | `ApplySharedPref` | Synchronous commits preserve acknowledgement/profile checkpoints, explicit contact-consent revocation, watch approvals and SOS retry state before later actions or process death. Converting them to asynchronous writes would change those durability semantics. |
| 16 | `UseKtx` | Explicit editor calls are retained with the existing commit-result handling and batching. KTX adoption is a style migration, including the two existing asynchronous measurement/emergency checkpoints. |
| 21 | `UnusedResources` | Retain translated strings from superseded QR/contact/authority screens as source migration debt. Release resource shrinking remains enabled. The externally consumed Wear discovery array is handled separately and is not baselined. |
| 9 | `LogNotTimber` | Retain existing Android operational logging conventions; this is a deferred logging-framework migration, with no new telemetry transport introduced. |
| 3 | `UseTomlInstead` | Retain existing explicit app dependency coordinates as version-catalog migration debt. |

Only these reviewed entries were appended to `Android/app/lint-baseline.xml`. API compatibility,
context ownership, user-visible localization and reserved Wear resource retention were not added to the baseline.

## Other release blockers corrected during validation

- Pin the Robolectric JVM runtime to supported API 34 while retaining the product target of API 37.
  Unit tests use the base `Application`; device/API 37 checks remain in the instrumented suites.
- Reapply stored telemetry consent when traffic conservation changes; recovery cannot grant consent,
  automatic crash uploads stay disabled, and satellite diagnostics respect the same gate.
- Add a regression test for consent revocation across conservation/recovery and satellite error reporting.

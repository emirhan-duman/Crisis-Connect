# Crisis Connect 1.2.0 Early Access · Beta 1

Release date: 20 October 2026. GitHub tag: `v1.2.0-beta.1`.

This is a pre-release for testing and feedback. The stable GitHub release remains `v1.1.9`.

## Versions

| Component | App version | Build |
| --- | --- | --- |
| Android phone | 1.2.0 | 69 |
| Wear OS | 1.2.0 | 70 |
| iOS app, extensions and watchOS apps | 1.2.0 | 38 |

The app version stays numeric for Apple distribution. The GitHub tag carries the beta sequence;
subsequent previews use `v1.2.0-beta.2`, `v1.2.0-beta.3`, and higher platform build numbers.

## Preview scope

- Updated messaging persistence, synchronization and authority MLS conversation migration
- Contact discovery consent, pairing and onboarding recovery
- SOS recovery and clearer connection-state handling
- Constrained-network traffic budgets and regional messaging clients
- Experimental Apple Watch and Wear OS companion / independent messaging work

Backend rollout flags still control availability. This release does not deploy backend functions,
change production rollout flags, or upload builds to either app store.

## Distribution

Android download availability and signature details are recorded in the GitHub release assets.
An AAB is an app-store upload artifact; install the universal APK for direct Android testing.
The developer-signed early-access APK uses certificate SHA-256
`503308ed16b6fc5a091184cadaa4ae3d5dbd4589c436cf3beea0e031273da86d`.
The stable Google Play-signed APK uses
`bb3bf8e42bafd2094c1c66e51c7642c5152ffda472fa57b5733ca340dd5e13db`.
These signatures differ, so this APK cannot update an installed Play/stable build. Use a separate
test device without that installed package. Keep existing app data intact; the release does not
provide a backup or migration mechanism for switching signing identities.
Play Integrity / App Check availability also depends on the installation source and backend policy.

iOS testing requires a separately distributed TestFlight build or a signed build for provisioned devices.
There is no public, universally installable iOS IPA in this GitHub release.

Native iOS static libraries are reconstructed locally and are excluded from the source mirror,
as in prior releases. The checked-in framework headers and manifests are not sufficient for a fresh
full iOS build without the matching native libraries. See `iOS/docs/SFU_GROUP_CALLS.md` and
`iOS/Packages/LibSignalClient/Package.swift` for the native build inputs.

## Validation

The GitHub release notes record the exact checks completed for this preview.
Android lint findings were reviewed individually; see the [triage record](1.2.0-beta.1-lint-triage.md).
The JVM test runtime is pinned to API 34, supported by Robolectric 4.12, while the product targets API 37.

## Known limitations

- Watch features are experimental, with account, device, OS and rollout requirements.
- Constrained satellite support depends on OS, device and carrier connectivity; no satellite field validation is claimed here.
- Regional failover requires backend configuration; source availability alone does not enable it.
- SFU group calls with MLS frame encryption remain experimental and gated.
- Existing privacy boundaries still apply: SOS dashboard reports and assistant cloud prompts are not end-to-end encrypted.

Report reproduction steps, platform, OS version and app build in a
[GitHub issue](https://github.com/emirhan-duman/Crisis-Connect/issues/new/choose).
